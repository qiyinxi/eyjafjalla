一个以**人物美学与故事**为核心的非官方同人展示页：术师（本体，粉焰）与医疗（纯烬，白灰）两套主题，一键切换。

## 运行

纯静态页面，无需构建。任选其一：

- **推荐**：在本目录运行 `python serve.py`（默认 0.0.0.0:25568；只在本机看用 `--host 127.0.0.1`），然后打开 <http://localhost:25568>
- 也可以用 `python -m http.server 5173`（没有压缩与分段，MV 的音乐会整段下载完再播）
- 也可以直接双击 `index.html`（未验证）：部分浏览器在 `file://` 下会限制跨域图片，此时粒子与「活」立绘会自动退化为静态立绘

需要联网：立绘、语音、字体与实景照片均为在线加载（PRTS 资源站、jsDelivr、Google Fonts、Wikimedia Commons 等）。
小剧场、桌宠与 MV 用到的官方 Spine 小人和 MV 里的剧情立绘卡片随站点一起放在 `assets/official/`，先取本地，本地缺文件时才退回 PRTS 资源站。
资源没加载出来时页面不显示错误提示，而是隐藏对应内容、在后台悄悄重试。
在地址后加 `?skip` 可跳过加载页；加 `?debug` 会在控制台暴露调试对象（`__pets`、`__hero`…）。

## 性能

- 离屏的区块（故事区按章节粒度）暂停其中全部 CSS 动画；标题流光由定时器低频推进，不让主线程逐帧工作
- 法阵每一圈装在独立的 div 里旋转（直接转 SVG 根元素时里面的符文文字会每帧重排）
- 各个 WebGL / 画布循环 30–60 帧封顶，看不见时停止；所有桌宠共用一个离屏 WebGL 上下文和一个 rAF 循环：位移 60 帧，骨骼绘制 30 帧（睡着 15 帧）且错开半帧
- 剧场布景：静态部分是一张 SVG，会动的烟、云、光、粒子都是独立的小块，只做 transform / opacity 动画（交给合成器）；站在标题线上的桌宠挂进页面，滚动时由合成器带着走
- 固定在顶上的导航、首屏动作条不用 `backdrop-filter`（背后的 WebGL 背景每帧都在变，毛玻璃会每帧重算）；插画的发光用多层半透明描边，不用高斯模糊
- 故事区的插画分成静止底图 + 会动的小图层（只动 transform / opacity）；横幅全景和两幅整屏场景的底图在空闲时用 CPU 画布分条“烘焙”成位图，显卡只贴一张图——大幅矢量画第一次上屏时要现编一批着色器，会卡上一两百毫秒
- 页内锚点跳转到站后会再校正一次（沿途区块用的是 `content-visibility` 的估计高度，渲染出来会变）
- 声景：关掉声音或切到后台时挂起整个音频上下文（与没有声音时一样，0 开销）；开着时实测约占一个 CPU 核的 1.5–3%（主线程约 0.2%）。噪声与纹理在 Worker 里只生成一次；用算法混响代替卷积混响（后者一项就要约 3%），没有声音送进去时整套断开；滤波与慢速包络用 k-rate；用不到的声层淡出后拆除；助听器开着时把透明的滤波器摘出链路
- MV：只在“正在播放 + 舞台看得见 + 页面在前台”时逐帧渲染（默认 1280×720，帧耗时高时自动降分辨率、降到 30 帧；「省电」固定 960×540 · 30 帧）；静态布景按分辨率缓存成位图，粒子由时间解析地算出（可以任意跳转）；实测每帧 CPU 平均约 1 ms。全屏放映时暂停页面背景着色器与前景粒子；歌曲边下边播（`serve.py` 支持 Range；换成不支持 Range 的服务器时自动改为整段下载再播）；离区块很远时丢掉渲染器与它的缓存
- `serve.py`：文本文件 gzip 压缩（脚本约缩到三分之一）、Range 分段、HTTP/1.1 长连接、ETag / 304——手机隔着外网访问时明显更快
- `lab/cdp.mjs` 可以在真实显卡上录制追踪（各线程忙碌时间、每帧重绘的节点、动画能否交给合成器）；`lab/scenes.html` 一次画出全部章节插画与剧场布景
